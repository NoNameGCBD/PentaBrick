## 1. 게임 개요

### 1.1 한 줄 소개
다섯 방향(상·전·후·좌·우)의 평면도를 보고, 여섯 가지 색의 정육면체 블록을 쌓아 똑같은 구도의 입체 모형을 만드는 공간 추론 퍼즐 게임.

### 1.2 장르와 플랫폼
- 장르: 싱글플레이 퍼즐
- 플랫폼: 웹 브라우저 (PC 우선, 모바일 화면 대응)
- 플레이 시간: 문제당 1~10분

### 1.3 핵심 재미
- 2D 평면도 다섯 장을 머릿속에서 3D로 조립하는 공간 추론
- "가능한 문제처럼 보이지만 실제로는 모순이 있는" 불가능 문제를 가려내는 추리
- 블록을 정확히 다 써야 하므로 "보이지 않는 안쪽 블록"까지 고려해야 하는 깊이

## 2. 게임 규칙

| 번호 | 규칙 |
|---|---|
| 1 | 시작 시 정답 모형의 다섯 방향 평면도와 사용 가능한 블록의 색별 개수가 공개된다. |
| 2 | 정육면체 블록을 쌓아 다섯 평면도의 조건을 모두 만족하는 모형을 만든다. |
| 3 | 완성하면 "정답 제출", 구현이 불가능한 구조라고 판단하면 "불가능"을 누른다. |
| 4 | 정답 제출: 정답이면 +1점, 오답이면 -1점. |
| 5 | 불가능 선언: 실제로 불가능한 문제면 +2점, 가능한 문제면 -2점. |

### 2.1 확정된 세부 규칙
| 항목 | 결정 | 이유 |
|---|---|---|
| 공중에 뜬 블록 | 허용하지 않음. 모든 블록은 바닥이나 다른 블록 위에 있어야 한다. | 실물 블록으로 만드는 느낌을 유지 |
| 블록 사용 개수 | 주어진 블럭 개수를 **정확히** 모두 사용해야 한다(전부 사용하지 않더라도 정답 제출 자체는 가능). | 안쪽에 숨은 블록까지 추론하게 만듦 |
| 평면도의 정보 | 실루엣뿐 아니라 **색까지** 표시된다. | 색 가림 모순이라는 추리 요소 제공 |
| 하(아래) 평면도 | 없음. 다섯 방향만 공개된다. | 바닥에 가려진 블록은 자유도로 남겨 둠 |
| 플레이 형식 | 싱글플레이 | |
| 시간 | 문제별 소요 시간을 기록한다. 시간 가산점은 추후 결정. | |

### 2.2 정답의 정의
플레이어의 모형이 다음 두 조건을 모두 만족하면 정답이다.
1. 플레이어 모형의 다섯 평면도가 문제의 평면도와 칸 단위로 완전히 일치한다.
2. 색별 블록 사용 개수가 문제에서 준 개수와 정확히 같다.

정답 모형은 여러 개일 수 있다(어느 방향에서도 보이지 않는 안쪽 블록의 배치가 다른 경우). 따라서 출제자의 원본 모형과 직접 비교하지 않고 위 두 조건만 검사한다.

### 2.3 불가능 문제의 정의
위 두 조건을 만족하는 모형이 하나도 존재하지 않는 문제. 대표적인 모순 유형:
- **실루엣 모순**: 한 평면도에서는 블록이 있어야 할 칸이 다른 평면도에서는 비어 있다.
- **색 가림 모순**: 맨 앞줄처럼 가려질 수 없는 위치의 블록 색이 두 평면도에서 다르다.
- **블록 수 모순**: 평면도대로 만들면 반드시 필요한 색의 개수가 주어진 개수와 맞지 않거나, 남는 블록을 숨길 자리가 없다.

## 3. 게임 흐름

```
[문제 시작] ─ 평면도 5개, 색별 블록 수, 타이머 시작
     │
     ▼
[풀이] ─ 블록 놓기 / 칠하기 / 지우기, 실행 취소, 시점 전환
     │
     ├─ "정답 제출" (블록을 정확히 다 썼을 때만 활성화)
     │        └─ 판정 → 정답 +1 / 오답 -1
     │
     └─ "불가능"
              └─ 판정 → 불가능 문제 +2 / 가능 문제 -2
     │
     ▼
[결과 화면] ─ 결과·점수 변동·소요 시간·(오답 시) 틀린 평면도 목록
     │        (가능 문제) "정답 모형 보기"  (불가능 문제) 모순 이유 설명
     ▼
[다음 문제] ─ 샘플 모드: 다음 샘플 / 생성 모드: 새 seed로 생성
```

- 결과 화면에서는 모형 편집이 잠긴다.
- 점수는 누적되며 모드를 바꿔도 유지된다. 페이지를 새로고침하면 0으로 돌아간다.

## 4. 문제 체계

### 4.1 문제 모드
| 모드 | 내용 |
|---|---|
| 샘플 | 손으로 만든 문제 6개(가능 4개, 불가능 2개)를 순서대로 낸다. 마지막 문제 다음은 처음으로 돌아간다. |
| 쉬움 / 보통 / 어려움 | 난이도 설정에 따라 문제를 자동 생성한다. 현재는 모두 가능한 문제다. |

### 4.2 난이도 설정 (자동 생성)
| 난이도 | 바닥 격자 | 최대 높이 | 색 가짓수 | 총 블록 수 | 칸당 기둥 확률 |
|---|---|---|---|---|---|
| 쉬움 | 3×3 | 3 | 3 | 6~10 | 60% |
| 보통 | 4×4 | 3 | 4 | 12~20 | 65% |
| 어려움 | 5×5 | 3 | 6 | 22~36 | 65% |

### 4.3 자동 생성 방식
1. 여섯 색 중 난이도의 색 가짓수만큼 무작위로 고른다.
2. 바닥 칸마다 "칸당 기둥 확률"로 기둥을 세운다. 높이는 낮은 쪽이 더 자주 나오도록 치우친 분포를 쓴다.
3. 각 블록 색을 팔레트에서 무작위로 정한다.
4. 품질 검사를 통과할 때까지 1~3을 반복한다.
   - 총 블록 수가 범위 안일 것
   - 고른 색을 모두 한 번 이상 사용할 것
   - 높이 2 이상인 기둥이 하나 이상 있을 것 (한 층짜리 평면 문제 제외)
5. 완성된 모형의 평면도와 색별 개수를 문제로 낸다. 정답 모형을 먼저 만들었으므로 해가 반드시 존재한다.

### 4.4 문제 코드와 공유
- 문제마다 32비트 seed가 있고, 같은 난이도와 seed는 항상 같은 문제를 만든다.
- seed는 36진수 짧은 코드로 표시한다. 예: `보통 · 1p0qp`
- 주소에 `?mode=normal&seed=1p0qp` 형태로 기록되어 새로고침해도 같은 문제가 유지되며, "링크 복사"로 다른 사람에게 같은 문제를 보낼 수 있다.

### 4.5 샘플 문제 목록
| 번호 | 크기 | 블록 | 성격 |
|---|---|---|---|
| p1 | 3×3×3 | 7 | 첫 문제. 높이 2까지. |
| p2 | 3×3×3 | 12 | 높이 3 기둥과 가려지는 블록 |
| p3 | 3×3×3 | 9 | **불가능** (색 가림 모순): 상 평면도의 앞줄 꼭대기 색이 전 평면도에 없음 |
| p4 | 4×4×4 | 16 | 중간 규모 |
| p5 | 3×3×3 | 6 | **불가능** (블록 수 모순): 필요한 초록이 부족하고 보라를 숨길 자리가 없음 |
| p6 | 4×4×4 | 20 | 안쪽에 가려진 블록이 있어 정답이 여러 개 |

불가능 샘플 두 개는 테스트의 전수 탐색으로 "해가 없음"을 검증했다.

## 5. 화면 명세

### 5.1 레이아웃
```
┌──────────────────────────────────────────────────────────────┐
│ PentaBrick 프로토타입        문제 보통·1p0qp (4×4×3)  점수 3  시간 01:24 │
├────────────┬──────────────────────────────┬──────────────────┤
│ 평면도     │                              │ 문제             │
│  상 [목표][내 모형] 일치 │        3D 에디터           │  샘플/쉬움/보통/어려움 │
│  전 …      │     (드래그 회전, 휠 확대)   │  새 문제  링크 복사 │
│  후 …      │                              │ 블록 (팔레트 6색)  │
│  좌 …      │                              │ 도구 놓기/칠하기/지우기 │
│  우 …      │  [시점: 기본 상 전 후 좌 우]   │ 제출 / 결과        │
└────────────┴──────────────────────────────┴──────────────────┘
```
- 3열 구성: 평면도 패널(300px) / 3D 화면(가변) / 조작 패널(290px)
- 화면 폭 980px 이하: 세로 1열로 바뀌고 3D 화면이 맨 위로 온다.

### 5.2 상단 바
| 항목 | 내용 |
|---|---|
| 문제 | 샘플: `샘플 2 / 6 (3×3×3)`, 생성: `보통 · 1p0qp (4×4×3)` |
| 점수 | 누적 점수 |
| 시간 | 현재 문제 경과 시간 mm:ss. 결과 화면에서는 제출 시점에 멈춘다. |

### 5.3 평면도 패널 (왼쪽)
- 상·전·후·좌·우 순서의 카드 5개. 각 카드에 목표 평면도를 색칠된 격자로 표시한다.
- 방향 안내 문구: 상 "위에서 · 아래쪽이 앞", 후 "뒤에서 · 좌우 반전", 좌 "왼쪽에서 · 오른쪽이 앞", 우 "오른쪽에서 · 왼쪽이 앞".
- **연습용 옵션** "내 모형의 평면도 표시"가 켜져 있으면(기본값 켜짐) 목표 옆에 내 모형의 현재 평면도를 나란히 보여주고, 일치하면 카드 테두리가 초록으로 바뀐다. 정식 난이도에서는 끄는 것을 전제로 한다.

### 5.4 3D 에디터 (가운데)
| 조작 | 동작 |
|---|---|
| 바닥 칸 또는 블록 좌클릭 (놓기 도구) | 그 칸의 맨 위에 선택한 색의 블록을 쌓는다. 미리보기(반투명 블록)가 놓일 위치를 보여준다. |
| 블록 좌클릭 (칠하기 도구) | 그 블록의 색을 선택한 색으로 바꾼다. |
| 블록 좌클릭 (지우기 도구) 또는 **우클릭** | 그 블록을 지운다. 위에 있던 블록은 한 칸씩 내려온다. |
| 드래그 | 카메라 회전. 5px 이상 움직이면 클릭이 아니라 회전으로 본다. |
| 휠 | 확대/축소 |
| 시점 버튼 | 기본(앞-오른쪽-위 비스듬히) / 상 / 전 / 후 / 좌 / 우 |

- 바닥 둘레에 "앞·뒤·좌·우" 라벨을 표시해 평면도 방향과 대응시킨다.
- 카메라는 바닥 아래로 내려가지 않는다(하 평면도가 없는 규칙과 일치).
- 선택한 색의 남은 개수가 0이거나 기둥이 최대 높이면 놓을 수 없고 미리보기도 뜨지 않는다.

### 5.5 조작 패널 (오른쪽)
| 섹션 | 구성 |
|---|---|
| 문제 | 모드 선택(샘플/쉬움/보통/어려움), 새 문제(샘플 모드에서는 "다음 샘플"), 링크 복사(생성 모드만) |
| 블록 | 색 6칸 팔레트. 각 칸에 색 이름과 `남은 수/전체 수`. 문제에 없는 색은 비활성. 선택 중인 색은 파란 테두리. 머리글에 `사용 n / 전체` |
| 도구 | 놓기 / 칠하기 / 지우기 (단축키 Q/W/E) |
| 편집 | 실행 취소 / 다시 실행 / 초기화 (초기화도 실행 취소 가능) |
| 옵션 | 내 모형의 평면도 표시 (연습용) |
| 제출 | 정답 제출(±1), 불가능(±2). 정답 제출은 블록을 정확히 다 썼을 때만 활성화. 생성 모드에서는 "아직 모두 가능한 문제" 안내 |
| 결과 | 결과 상자(5.6) |
| 조작법 | 짧은 도움말 |

### 5.6 결과 상자
| 경우 | 제목 | 내용 |
|---|---|---|
| 정답 제출, 정답 | 정답입니다 +1점 | 다섯 평면도와 블록 수가 모두 일치 |
| 정답 제출, 오답 | 오답입니다 −1점 | 일치하지 않는 평면도 이름 목록 또는 "색별 블록 수 불일치". 불가능 문제였다면 그 이유도 표시 |
| 불가능 선언, 정답 | 맞습니다, 불가능한 문제입니다 +2점 | 모순 이유 설명 |
| 불가능 선언, 오답 | 틀렸습니다, 구현 가능한 문제입니다 −2점 | "정답 모형을 확인해 보세요" |

공통: 소요 시간, (가능 문제) "정답 모형 보기" 버튼, "다음 문제" 버튼.
"정답 모형 보기"를 누르면 3D 화면에 정답 모형이 나타나고 평면도 패널은 모두 "일치"로 바뀐다.

## 6. 데이터 명세

### 6.1 좌표계 (앞에서 바라보는 기준)
- x: 왼쪽(0) → 오른쪽(size-1)
- y: 바닥(0) → 위(height-1)
- z: 뒤(0) → 앞(size-1)

### 6.2 모형 (model)
```
{ size, height, columns }
columns[z * size + x] = [아래→위 순서의 색 번호]   예) [5, 1] = 파랑 위에 빨강
```
- 칸마다 "색 스택"으로 저장하므로 중간이 빈 상태를 표현할 수 없다. 뜬 블록 금지 규칙이 자료구조 차원에서 보장된다.
- 편집 함수(놓기/지우기/칠하기)는 원본을 바꾸지 않고 새 모형을 돌려준다. 실행 취소는 이전 모형 객체를 보관하는 것으로 구현한다.

### 6.3 평면도 (view)
```
view[row][col] = 색 번호 또는 0(빈칸)
```
- row: 위→아래. 옆면은 높은 층이 위, 상 평면도는 뒤쪽 줄이 위.
- col: 그 방향에 서서 봤을 때의 왼쪽→오른쪽.
- 값: 시선이 처음 만나는 블록의 색.

| 방향 | 왼쪽 열 | 가까운 순서 |
|---|---|---|
| 전 | x=0 | z = size-1 → 0 |
| 후 | x=size-1 (좌우 반전) | z = 0 → size-1 |
| 좌 | z=0 (뒤) | x = 0 → size-1 |
| 우 | z=size-1 (앞) | x = size-1 → 0 |
| 상 | x=0, 위쪽 행이 z=0(뒤) | 각 칸의 맨 위 블록 |

### 6.4 문제 (puzzle)
| 필드 | 내용 |
|---|---|
| id | 식별자. 샘플 `p1`…, 생성 `normal-1p0qp` |
| size, height | 격자 크기 |
| views | `{ top, front, back, left, right }` 다섯 평면도 |
| counts | 색별 블록 수 배열(인덱스 = 색 번호, 0번은 항상 0) |
| solvable | 해가 있으면 true |
| answer | 정답 모형(불가능 문제는 null) |
| reason | 불가능 문제의 모순 설명 |
| difficulty, seed | 생성 문제에만 있음 |

### 6.5 게임 상태 (state)
| 필드 | 내용 |
|---|---|
| mode | `sample` / `easy` / `normal` / `hard` |
| puzzleIndex | 샘플 모드의 순번 |
| puzzle, model | 현재 문제, 편집 중인 모형 |
| past, future | 실행 취소/다시 실행 스택 |
| color, tool | 선택한 색과 도구 |
| score | 누적 점수 |
| phase | `playing` / `result` |
| result | `{ kind, correct, delta, views, countsMatch, elapsedMs }` |
| startedAt | 문제 시작 시각 |
| showMine, showingAnswer | 연습 옵션, 정답 모형 표시 중 |

## 7. 기술 구조

### 7.1 기술 스택
| 영역 | 선택 | 비고 |
|---|---|---|
| 언어 | JavaScript (ES 모듈) | 빌드 도구 없음. 브라우저가 소스를 직접 불러온다. |
| 3D | three.js 0.170 (CDN, importmap) | 인터넷 연결 필요 |
| UI | 순수 DOM, 상태 변경 시 innerHTML 재생성 | |
| 상태 관리 | 단일 state 객체 + 구독(subscribe) | |
| 테스트 | 자체 미니 테스트 도구. 브라우저(`tests/`)와 macOS jsc 양쪽에서 실행 | |
| 호스팅 | GitHub Pages (main 브랜치 루트) | 정적 파일만 |
| 백엔드 | 없음 | 싱글플레이라 불필요 |

### 7.2 모듈 구조
```
index.html, styles.css        페이지 뼈대와 스타일
src/main.js                   시작점: URL 읽기, 상태 시작, 화면 생성
src/core/model.js             모형 자료구조와 편집
src/core/projection.js        평면도 계산
src/core/judge.js             판정과 점수
src/core/puzzles.js           샘플 문제, 문제 객체 생성
src/core/generator.js         난이도별 자동 생성, seed 코드
src/game/state.js             상태, 액션, 실행 취소, 타이머
src/ui/scene.js               three.js 에디터
src/ui/panels.js              DOM 패널
src/ui/colors.js              색 정보
tests/core.test.js            단위 테스트 26개
```
- 의존 방향: `ui → game → core`. core는 화면과 상태를 모르며 서버에서도 그대로 쓸 수 있다.
- 데이터 흐름: 화면은 state를 구독해 그리고, 모든 변경은 actions를 통해서만 일어난다.

### 7.3 테스트 범위 (26개)
- 모형: 쌓기/지우기/칠하기, 경계 검사, 불변성, 500회 무작위 편집 후 뜬 블록 없음
- 평면도: 각 모서리 블록의 방향 확인, 전후/좌우 가림, 상 평면도, 가로·높이가 다른 격자
- 판정: 정답 통과, 원본과 다른 정답 인정, 블록 수 불일치 오답, 틀린 평면도 보고, 점수 ±1/±2
- 샘플: 가능 문제의 정답 통과, 3×3 문제의 가능/불가능 표시를 전수 탐색으로 검증
- 생성기: seed 재현성, 코드 변환, 난이도별 150개씩 조건 만족과 정답 통과

### 7.4 배포
- `git push` → GitHub Pages가 main 브랜치를 자동 배포 (약 20~60초)

## 8. 주요 설계 결정과 근거

| 결정 | 근거 |
|---|---|
| 정답 모형과 직접 비교하지 않고 평면도·개수만 검사 | 같은 평면도를 만드는 모형이 여러 개일 수 있어 규칙상 모두 정답 |
| 칸별 색 스택 저장 | 뜬 블록 금지를 자료구조로 보장, 투영 계산 단순화 |
| 불변 모형 객체 | 실행 취소/다시 실행을 "객체 보관"만으로 구현 |
| 블록을 정확히 다 써야 제출 버튼 활성화 | 실수로 인한 감점 방지. 정보 유출 없음 |
| 연습용 "내 모형 평면도" 기본 켜짐 | 프로토타입 검증 편의. 정식 난이도에서는 끄는 전제 |
| seed 기반 생성 | 문제 공유·재도전·버그 재현 가능 |
| 정답을 먼저 만들고 평면도를 내는 생성 방식 | 솔버 없이도 해의 존재가 보장됨 |
| 빌드 도구 없는 순수 JS | 개발 환경에 Node.js가 없었음. 핵심 로직은 TypeScript로 옮기기 쉬운 구조 |

## 9. 알려진 제약

- 자동 생성 모드에는 불가능 문제가 없다. 따라서 생성 모드에서 "불가능"은 항상 -2점이다. (4단계에서 해결)
- 정답과 가능/불가능 정보가 브라우저로 내려간다. 공개 랭킹을 운영하려면 서버 판정으로 바꿔야 한다.
- 점수는 새로고침하면 사라진다.
- three.js를 CDN에서 불러오므로 오프라인에서는 동작하지 않는다.
- 시간 가산점이 아직 없다(소요 시간만 기록).
