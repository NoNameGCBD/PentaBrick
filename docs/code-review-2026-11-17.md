# PentaBrick 코드 분석 및 UI 개선 — 2026-11-17

대상: Assets/PentaBrick의 Core, Game, View, Editor, Tests, PlayTests 및 명령줄 테스트 프로젝트.

## 전체 구조 평가

- Core가 UnityEngine에 의존하지 않아 평면도·판정·문제 생성·탐색을 Unity 없이 검증할 수 있다.
- Model은 편집 때 새 모형을 만들고 변경되지 않은 기둥 배열을 공유한다. 실행 취소/다시 실행과 잘 맞는다.
- Judge는 원본 정답과 직접 비교하지 않고 다섯 평면도와 색별 개수를 검사한다. 복수 정답을 허용하는 퍼즐 규칙에 적합하다.
- Generator의 seed 재현성과 Solver의 Unknown/Unsolvable 구분은 유지해야 한다. 탐색 한도 초과를 불가능으로 처리하면 오출제가 생긴다.
- GameState는 진행·점수·튜토리얼 연습 판정을 관리하고 View는 이를 읽는다. 현재 규모에서 합리적인 분리다.

## UI 디자인 방향 및 구현

공간 추론 퍼즐의 ‘작업대’ 느낌을 남색·시안·색 블록으로 표현한다. 외부 이미지나 새 패키지를 사용하지 않는다.

- 메인: 미세한 격자 배경, 실제 첫 샘플 평면도 세 장, 제목과 주 행동 버튼의 위계.
- 모드 선택: 네 난이도의 단계 블록, 고유 강조색, 격자 크기와 짧은 설명.
- 게임: 브랜드/문제 코드 헤더, 번호가 있는 평면도 카드, 커진 카드 내부 격자, 둥근 색 타일.
- 작업대: 사용 블록 수/전체 블록 수, 격자 크기, 사용량 진행 막대. 제출 가능할 때 녹색으로 표시한다.
- 입력: 기존 단축키·튜토리얼·44px 조작 버튼을 유지하고 키보드 포커스 스타일을 추가한다.
- 모바일: 기존 세로 화면 배치 분기를 유지한다. 튜토리얼/결과에서는 작업대 안내를 숨겨 겹침을 줄인다.

## 후속 수정 권장 순서

### 1. UI 부분 갱신 — 성능과 포커스 유지

GameUI.Build는 여전히 상태 변경 시 root.Clear 후 전체 화면을 만든다. 색 선택 같은 작은 변경도 새 VisualElement와 콜백을 생성하며 키보드 포커스가 사라질 수 있다. 다음 단계에서는 화면 전환만 전체 재구성하고 색 칩·버튼 활성 상태·평면도 등은 기존 요소를 갱신하는 구조를 권장한다. 이번에는 화면 흐름 변경 위험을 줄이기 위해 3D 재생성과 불필요한 평면도 연산부터 줄였다. 실제 성능 수치는 프로파일링이 필요하다.

### 2. 문제 생성 중 응답성 — 기기 실측 후 개선

Generator.Generate는 메인 스레드에서 호출된다. 불가능 문제 생성은 최대 30번의 변형 시도와 각 Solver의 노드 한도를 사용하므로 일부 seed와 느린 기기에서 화면 정지가 생길 가능성이 있다. 현재 지연을 실측한 것은 아니다. seed별 소요 시간을 측정하고 필요하면 로딩 표시와 프레임 분할/플랫폼별 백그라운드 실행을 도입한다. 난수 호출 순서와 기존 seed 결과는 유지해야 한다.

### 3. 점수·진행 저장 및 타이머 정책

Score는 메모리에만 있으므로 앱 재실행 시 사라진다. 장기 진행을 의도한다면 버전이 있는 저장 구조에 점수·모드·seed·모형을 저장하고 불완전한 저장을 복구하는 정책이 필요하다. ElapsedMs는 실제 경과 시간이므로 일시정지 메뉴에서도 계속 흐른다. 시간 보너스가 있는 만큼 메뉴 시간을 포함할지 먼저 정해야 한다. 이는 현재 규칙의 선택사항으로 남겼다.

### 4. 데이터 경계 강화

Puzzle의 Views/Counts와 Model.Column은 읽기 전용 의도로 사용되지만 원본 배열을 수정할 수 있는 경로가 있다. 사용자 제작 문제나 저장 파일 가져오기를 추가하기 전에 크기·높이·색·개수·평면도 치수를 검증하고 외부에 노출하는 데이터를 보호해야 한다. 특히 Model.FromColumns는 Empty와 달리 크기/높이 양수 검증이 없다. 현재 내장 데이터 경로의 실제 오류로 확인된 사항은 아니다.

### 5. 접근성과 기기 검증

현재 평면도는 색 구분에 크게 의존한다. 색약 사용자를 위한 패턴/기호 표시를 평면도·색 칩·3D 블록에 일관되게 적용하는 것이 다음 디자인 과제다. 실기기 터치, WebGL 클립보드/링크, Windows 빌드는 별도 확인이 필요하다.
